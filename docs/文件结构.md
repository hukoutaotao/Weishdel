# 四、按依赖顺序详细讲解源码

## 4.1 构建入口

### `D:\1\CMakeLists.txt`

这是整个项目的构建总入口。

它建立了四个主要目标：

1. **`AutoChessCore`**
   - 纯 C++ 静态库
   - 包含配置、经济、战斗、Match、AI 等核心逻辑
   - 不依赖 SFML
   - 使核心逻辑可以被独立测试

2. **`AutoChessGame`**
   - 图形化游戏程序
   - 链接 `AutoChessCore`
   - 链接 SFML Graphics、Window、System
   - 编译 `D:\1\src\game` 下的应用、页面和渲染代码

3. **`AutoChessTests`**
   - 自动测试程序
   - 链接核心库
   - 加入少量运行路径代码进行路径测试
   - 不需要打开游戏窗口

4. **`AutoChessDist`**
   - 将游戏 EXE、三个 SFML DLL 和 `data` 复制到 `D:\1\dist`
   - 形成独立发布目录

这个文件还把 C++ 标准设置为 **C++17**，当前构建流程面向 **MSVC + Ninja**。

一个需要明确指出的细节是：

> `D:\1\src\game\controllers\BootstrapComputerController.hpp/.cpp` 存在于源码目录，但没有加入当前 `AutoChessGame` 的正式源文件列表。

因此它属于保留下来的早期或辅助电脑控制器，并不是正式版本正在使用的 AI。正式 AI 是 `D:\1\src\core\ai\AiController.*`。

### `D:\1\CMakePresets.json`

# 十、整体代码结构的关键特点

## 1. 核心逻辑与 SFML 分离

`D:\1\src\core` 不依赖 SFML，`D:\1\src\game` 才依赖 SFML。

这样核心逻辑可以：

- 独立测试
- 无窗口运行
- 被脚本对局使用
- 保持稳定和可复现

## 2. 数据驱动

单位、技能、分队和地图都来自配置文件，不需要为每个数值改 C++。

## 3. 命令驱动

真人和 AI 都只能提交 `GameCommand`，不能直接修改 Match。

```text
界面/AI
→ GameCommand
→ Match::submit()
→ 具体服务
```

## 4. 只读视图

控制器只拿到 `ReadOnlyGameView`，而且对手信息经过裁剪，降低了越权和作弊式读取的可能。

## 5. 固定帧模拟

核心战斗以 60Hz 固定步长推进，不直接依赖屏幕渲染帧率。

```text
渲染可以快或慢
核心仍按固定 1/60 秒推进
```

## 6. 持久单位与战斗单位分离

```text
OwnedUnit：跨回合存在
BattleUnit：单场战斗临时副本
```

这是项目中非常合理的一层边界。

## 7. 事务式更新

配置加载、商店、合成和回合结算等操作普遍采用：

```text
复制或临时构造
→ 完整校验
→ 成功后提交
```

因此失败操作不容易留下半修改状态。

## 8. 测试覆盖层次完整

测试不是只测函数，还覆盖：

- 单元规则
- 配置非法输入
- 经济组合
- 战斗模拟
- Match 状态机
- AI 策略矩阵
- 完整脚本对局
- 发布路径
