# 自走棋对战系统调试记录

日期：2026-08-22

## 1. 调试原则

1. 先把问题归类为 CMake 配置、编译、链接、DLL 启动、数据加载、核心规则或 GUI 交互。
2. 配置和规则问题优先写最小自动测试；GUI 问题使用固定点击流程和运行截图复现。
3. 故障注入只在 `build/qa-temp` 的隔离副本中进行，不删除正式 `data` 或 `dist` 文件。
4. 每次修复后先运行针对性检查，再运行完整 MSVC x64 Release 测试。
5. 每个结论必须记录“现象—原因—修复—验证”，不能只写“已解决”。

## 2. 调试案例一：CMake 工程文件名错误

### 现象

初始工程文件使用 `CMakeList.txt`，执行 CMake 配置时无法按约定找到顶层工程文件，因此不能生成构建目录。

### 原因

CMake 顶层文件的固定名称是 `CMakeLists.txt`，其中 `Lists` 必须为复数。文件内容即使正确，文件名不符合约定也不会被识别。

### 修复

将工程文件改为 `CMakeLists.txt`，并在其中明确 C++17、MSVC、SFML 2.6.2、Core/Game/Tests 和 Dist 目标。

### 验证

使用 `cmake --preset msvc-release --fresh` 重新配置成功；Release 构建完成 47/47 个步骤且退出码为 0。证据为 `docs/test-results/release-build-2026-08-22.log`。

## 3. 调试案例二：发布包依赖开发目录数据

### 现象

开发目录内运行正常，但把 EXE 和 DLL 复制到项目外后，数据查找仍可能依赖源码绝对路径；这种情况下发布包并不真正独立，换电脑或删除开发目录后会失败。

### 原因

应用层直接使用编译期源码数据路径，未优先根据 `AutoChessGame.exe` 所在目录解析 `data`。

### 修复

增加无 SFML 依赖的运行路径工具：先取得可执行文件目录；若 EXE 旁存在 `data`，必须使用该目录；只有旁置 `data` 不存在时才允许开发目录回退。`GameApp` 通过构造参数接收已经选定的数据目录。

### 验证

1. 新增 5 个运行路径断言并通过完整 Release 测试。
2. `AutoChessDist` 生成 10 个必要文件。
3. 将发布包复制到项目外并以 `D:\` 为工作目录启动，窗口可创建并正常退出。
4. 临时移除外部副本的 `game.cfg` 后，错误路径明确指向外部 EXE 旁 `data`，没有读取 `D:\1\data`。

证据为 `docs/test-results/dist-verification-2026-08-22.log`。

## 4. 调试案例三：同帧索敌编号并列缺少直接断言

### 现象

规则要求“敌人首次进入攻击范围的帧相同时，选择较小战斗单位编号”。已有测试覆盖较早进入范围的目标，但没有直接构造两个目标同帧进入的并列场景，因此测试矩阵中存在覆盖缺口。

### 原因

生产选择器已经包含比较规则，但测试只验证了第一排序键，没有独立锁定第二排序键。后续改动可能破坏编号并列规则而不被发现。

### 修复

在 `tests/TestMain.cpp` 中构造编号为 3 和 2、同在第 4 帧进入范围的两个敌人，调用 `TargetSelector::update`，同时断言：

- 两个目标的首次入圈帧均记录为 4；
- 攻击者最终目标为较小编号 2。

新增测试代码块前保留一句用途注释，不修改生产规则。

### 验证

测试 `Target selector breaks same-frame ties by lower ID` 通过；10.4 回归为 396 PASS / 0 FAIL，后续加入运行路径测试后的最终结果为 402 PASS / 0 FAIL。证据为 `docs/test-results/priority-regression-matrix-2026-08-22.md` 和 `docs/test-results/final-release-tests-2026-08-22.log`。

## 5. 调试案例四：最终界面与文档仍保留开发期文字

### 现象

第 10 天编写独立使用说明时发现两处最终交付文字与实际状态不一致：

1. AI 选择页仍显示“第 9 天将接入完整策略”，会让验收者误认为三种 AI 尚未完成。
2. 报告把构建预设写成不存在的 `build-msvc-release`，而 `CMakePresets.json` 中实际名称是 `msvc-release`。

### 原因

开发阶段占位文案和早期报告草稿没有在功能完成后同步到最终项目配置。

### 修复

将 AI 选择页说明改为“请选择电脑的决策风格：进攻、防守或路线”；把报告中的配置、构建和 Dist 命令统一为真实预设 `msvc-release`。

### 验证

- 全项目可见文案扫描不再命中旧 AI 提示。
- 使用真实预设重新完成 MSVC x64 Release 编译和 402 项自动测试。
- 更新 AI 选择页正式截图，并重新生成、更新字段、导出和逐页检查 28 页课程报告。

## 6. 启动故障验收记录

所有故障都在带所有权标记的临时副本中注入，正式发布目录未被破坏。

| 故障样本 | 预期 | 实际验收 |
|---|---|---|
| 缺少 `game.cfg` | 指出缺失配置路径并受控退出 | 退出码 1，错误路径明确 |
| 缺少地图文件 | 指出缺失地图路径并受控退出 | 退出码 1，错误路径明确 |
| `max_rounds` 非法 | 指出字段和范围错误 | 退出码 1，中文诊断明确 |
| 缺少中文字体 | 指出字体加载失败 | 退出码 1，受控结束 |
| 缺少 SFML DLL | Windows 加载器拒绝启动 | 返回 `0xC0000135`，无游戏进程残留 |

证据为 `docs/test-results/runtime-acceptance-2026-08-22.log`。

## 8. 2026-08-25：新增 8×5 镜像绕行地图

### 现象与目标

根据手绘草图新增 `map_04`：黑格不可进入，叉号格可进入但不可部署，双方各 6 个部署格；第 5 行第 2 列及其余部署位均采用先进入中央、再从另一侧绕到敌方守卫的路线。

### 实现

- 新增 `data/maps/map_04.map`，网格为 8×5，并关于纵向中轴线镜像对称。
- 为 12 个部署格各配置一条路线，B 方路线是 A 方对应路线的水平镜像。
- 将正式配置加载顺序扩展为 4 张地图。
- 将 AI 完整对局矩阵扩展为 3 种策略 × 4 张地图 × 3 个分队，共 36 组。
- 增加地图尺寸、格子数量、镜像关系、手绘绕行路线和路线长度验收。

### 验证

- 地图静态校验：12 个障碍、14 个不可部署通行格、双方各 6 个部署格、双方各 1 个守卫。
- 路线静态校验：12 条路线全部上下左右连续、不穿障碍、终点正确，双方路线互为镜像。
- MSVC x64 Release 完整测试：422 PASS / 0 FAIL。
- AI MATRIX：36 组全部 `command_failures=0`、`rounds=3`。
