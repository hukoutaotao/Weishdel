# 开始游戏闪退修复记录（2026-08-26）

## 用户现象

启动 `dist/AutoChessGame.exe` 后，点击主菜单“开始游戏”会短暂卡顿并闪退；主菜单本身可以正常显示。

## 崩溃诊断

通过 Windows Application Error（事件 ID 1000）确认：

- 异常代码：`0xc0000374`
- 含义：Windows 堆损坏
- 故障模块：`ntdll.dll`
- 故障程序：`D:\1\dist\AutoChessGame.exe`

该现象与点击“开始游戏”后的页面创建时机一致。检查构建产物后发现，`MatchScreen.hpp` 在 2026-08-25 增加了 `deploymentPreview_` 成员，但 Release 增量构建没有重新编译仍包含该头文件的 `GameApp.cpp`。于是旧版 `GameApp.cpp.obj` 按旧的 `MatchScreen` 类布局分配对象，新版构造函数却按新的类布局写入成员，造成堆越界，最终触发 `0xc0000374`。

因此，问题根因是**构建依赖失效导致新旧对象文件混用**，不是开始游戏流程或对局规则本身的逻辑错误。

## 修复内容

1. 清理并完整重建 MSVC x64 Release，重新生成 `GameApp.cpp.obj`、`MatchScreen.cpp.obj` 和最终可执行文件。
2. 修正 `CMakeLists.txt` 中 Ninja/MSVC 的 `/showIncludes` 依赖前缀配置。当前 MSVC 输出为 UTF-8 中文前缀 `注意: 包含文件:  `，显式配置后 Ninja 能正确记录头文件依赖。
3. 保留 `CMakePresets.json` 原有配置，不再依赖未生效的 `VSLANG` 试验设置。
4. 将验证通过的 Release 程序同步到 `dist/AutoChessGame.exe`。

## 验证结果

- `GameApp.cpp.obj` 的 Ninja 依赖记录从 `#deps 0` 恢复为实际依赖（共 223 项），并包含 `src/game/screens/MatchScreen.hpp`。
- 临时修改 `MatchScreen.hpp` 时间戳后，Ninja 预演会同时重编译 `GameApp.cpp.obj`、`MatchScreen.cpp.obj` 并重新链接，说明后续头文件变更能够正确触发调用方重编译。
- 自动测试：全部通过，结果为 `PASS：422`、`FAIL：0`。
- 启动 `dist/AutoChessGame.exe` 并自动点击“开始游戏”后，进程保持运行，窗口仍响应。
- 本次回归测试期间没有产生新的 AutoChessGame.exe Application Error 事件。
- `build/msvc-release/AutoChessGame.exe` 与 `dist/AutoChessGame.exe` SHA-256 均为：
  `86F750D0507931A97C271C99E5E91EA839453F53AA9AC3B3988C0706B514F522`

## 影响范围

本次修复只涉及构建依赖跟踪和发布产物重建，没有修改核心游戏规则、对局状态机或开始游戏业务逻辑。
